# PUTTSEED — Architecture

## Layers

```
+--------------------------------------------------+
| unity/  (render, input, UI, audio, interpolation)|
|   -> quantizes input, forwards to core           |
|   -> reads sim state snapshots, never mutates    |
+--------------------------------------------------+
| core/src (netstandard2.1, zero UnityEngine)      |
|   FixedMath  : Fix64, Vec2Fix, FixRng (xorshift) |
|   Sim        : BallState, CourseData, GolfSim    |
|   CourseGen  : Generator, SolvabilityChecker,    |
|                DifficultyRater                   |
|   Replay     : ReplayCodec, GhostPlayer          |
|   Daily      : DailySeed                         |
+--------------------------------------------------+
```

## FixedMath

- `Fix64`: Q32.32 signed fixed-point on `long`. Mul/Div use 128-bit
  intermediates (`Math.BigMul` or manual hi/lo split) to avoid overflow.
  Sqrt via Newton iteration. No trig needed in the hot path: aim comes in
  as a quantized angle index, converted once via a precomputed fixed-point
  sin/cos table (1024 entries, generated by a test-verified tool, stored
  as `long[]` constants — table generation itself must not use runtime
  floats in core; generate offline, commit the table).
- `Vec2Fix`: value struct, standard ops, dot, lengthSq; `Length()` via
  Fix64 sqrt.
- `FixRng`: xorshift128, seeded, fully deterministic; the ONLY randomness
  source in core.

## Sim

- Fixed dt = 1/120 s (`Fix64` constant). `GolfSim.Tick()` advances one step.
- Ball: circle, semi-implicit Euler; rolling friction as exponential
  velocity damping (stronger inside sand polygons).
- Collision: circle vs segment. Use sub-stepping (split a tick if the
  travel distance exceeds a fraction of ball radius) instead of full swept
  collision — simpler, deterministic, sufficient at 120 Hz.
- Bumper: circle vs circle, restitution > 1 with a capped exit speed.
- Water: point-in-polygon test at rest OR while crossing; on trigger,
  apply penalty and teleport to last rest position.
- Hole capture: overlap + `speed < captureThreshold`, else rim-out impulse.
- Rest detection: `speedSq < eps` for N consecutive ticks → `IsAtRest`.
- **State hash:** FNV-1a over the raw fields of the sim state, exposed as
  `GolfSim.StateHash()`. This is the backbone of determinism tests.
- Zero heap allocation per tick.

## CourseGen

1. Corridor growth: from a start pad, grow a polyline of 4–8 segments with
   min/max turn-angle and length constraints inside a bounding box; widen
   into wall pairs; place hole at the end.
2. Decorate: 0–3 bumpers, 0–2 sand zones, 0–1 water zone, respecting
   clearance rules (never block the corridor fully).
3. **SolvabilityChecker:** breadth-first over shot sequences up to `par`
   depth. From each rest state, sample the quantized shot space on a
   coarse grid (e.g. every 8th angle × every 16th power), simulate with a
   tick cap, collect reachable rest states (deduplicated by position
   hash). Course is accepted only if the hole is reached within par.
   The found sequence is stored as the **author solution** (also used as a
   fallback ghost and for difficulty rating).
4. **DifficultyRater:** score from author-solution tightness (how few of
   the sampled shots succeed per step), corridor turn count, hazard count.
5. Rejected courses simply re-roll with the next sub-seed; generation must
   be bounded (give up after K attempts and relax decoration — never
   loosen the solvability requirement).

## Replay

- `ReplayCodec`: `[version:1][seed:8][shotCount:1][shots: shotCount × 3 bytes]`
  where a shot = 10-bit angle index + 8-bit power index + padding →
  base64url with `PUTT-` prefix. Round-trip unit tested.
- Playback = re-running the sim with decoded inputs. A replay that
  desyncs is a determinism bug by definition — there is a regression test
  replaying stored fixtures and asserting final `StateHash()`.

## Daily seed

`seed = SplitMix64(hash(utcDate.ToString("yyyyMMdd") + SALT))` — computed
locally, no backend. Practice mode draws random seeds from device entropy
(outside core, passed in).

## Unity layer

- `SimRunner` (MonoBehaviour): accumulates real time, steps
  `GolfSim.Tick()` at fixed 120 Hz, keeps last two states, renders at
  `t = interpolationAlpha`.
- Presentation reads positions as floats ONLY at the render boundary
  (`(float)fix64Value` conversion helper lives in unity/, not core/).
- Input: drag vector → angle index + power index → `ShotInput` struct.
- Ghosts: a second (or Nth) read-only sim instance stepped in lockstep.

## Test strategy

- **Unit:** Fix64 ops vs precomputed constants (including overflow edges),
  Vec2Fix, RNG sequences, point-in-polygon, segment collision cases.
- **Determinism:** same seed + same shot list → identical `StateHash()`
  after 10k ticks; run twice in-process and against committed golden
  hashes (catches accidental float leakage across refactors).
- **Property (1000 random seeds in CI):** generator always terminates;
  every accepted course is solvable; replay codec round-trips; author
  solution replayed reaches the hole.
- **Golden replays:** fixture files with expected final hashes.
- Unity EditMode tests only for the quantization boundary and SimRunner
  stepping logic.
